# 插件文档

`plugins/dsh-l0-control/README.md` 是**入口**（怎么装、怎么构建、工具清单）。
这个文件夹是**按功能模块展开的细节**——每个模块讲清「它解决什么问题、怎么设计的、关键数字、踩过什么坑」。

**两套编号，别混：**

- **`01`–`14` 是说明文档**，按模块顺序递归编号——它们是「这个东西怎么运作的」正文。
- **`A1` / `A2` 是附录**，**不占正文编号**：`A` = 附录。猜想与已知问题台账不属于「运作说明」，所以单独拎出来，正文编号因此始终连续、不留空洞。

## 一条阅读主线

如果只想读一篇，读 **02 派发与闸门**——它是这个插件最容易让人迷惑的地方（"为什么只派了 3 个"），也是设计密度最高的地方（四道闸门 + 预算作用域 + 失败分流 + 归因）。

## 这些文档的约定

- **数字都来自实测**，并标明口径（哪台机器、多少条数据）。没实测的地方会写「未经实测」。
- **讲「为什么」，不只讲「是什么」**。比如「最小堆反而更慢」这种反直觉结论，会给出测量值。
- **踩过的坑单独成段**，标注它是第几次出现。同一形态反复出现是这个仓库最值得记的事。

## 不在这个文件夹里的东西

- **按轮次的过程记录** → 管理区 `reports/`
- **设计草案与研究** → 管理区 `designs/_research/`（不随仓库分发）
- **历史架构决策** → 管理区各轮报告
