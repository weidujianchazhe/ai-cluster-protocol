# 08 · 工具面

> 29 个工具的入参、边界与常见误用。按**使用顺序**分组，不是按字母。

## 零、开工前

### `env_check`
无参数。一次给出：宿主服务、三处数据落点与各盘空间、按实测速率推算的规模上限。

| 字段 | 用途 |
|---|---|
| `ready` | **false 时看 `blockers`**，那是必须先解决的 |
| `blockers` | 缺 subagents / 缺 agentTeams / 会话盘装不下千级 |
| `hostServices` | 三个宿主服务在不在 |
| `storage` | 落点、各盘可用、告警、建议 |
| `scale.suggestedMaxAgents` | 按会话盘可用空间反推（保守：只用一半） |

**建议**：派第一个 Agent 之前调一次。

## 一、建图

### `wish_submit`
只记愿望，**不建图**。返回 GraphSpec 模板与建图指令。

> 误用：以为它会把愿望变成节点。它只登记意图。

### `graph_plan`
**零写入**校验预览。返回 `errors` / `warnings` / `wouldBeReady` / 拓扑序 / counts。

- `wouldBeReady` 只按 **deps** 推算（`basis: "deps-only"`），不含租约/闸门/巡检。
- 落图前**必须**先跑它——`graph_commit` 的校验与它同一套，但 plan 不会让你在发现问题前先写盘。

### `graph_commit`
校验通过才落图；**重复提交幂等**（同 spec 不会建两遍）；**失败零写入**。

### `graph_status`
读图状态。分页（默认 50/页，上限 500）。

包含：journal 摘要、快照状态、能力摘要、`hostServices`、`storage`、`dispatch` 视图、`graph`（节点最小投影）、`persistence`（含 `recoveryReport`）。

> 大图别指望它一次全给——用 `limit` / `offset`，或 `graph_export`。

### `graph_export`
导出人读投影（`capabilities.json` / `STATE.md`）。默认写到 `stateDir/export/`。

### `graph_checkpoint` / `graph_recover` / `graph_resume_plan`
| 工具 | 作用 |
|---|---|
| `graph_checkpoint` | 为分区落检查点（追加 `partition_checkpointed`） |
| `graph_recover` | 返回最近检查点 + 需重放的事件数（**不**真正重放） |
| `graph_resume_plan` | 按检查点逐节点对比 → `resume` / `skipCompleted` / `drift` |

> `drift` 表示「检查点说 done，但当前状态退回了」——**journal 被改过**，要报警而不是继续。

## 二、派活与租约

### `dispatch`
派活循环控制。`mode`: `off` / `interval` / `resident`；默认 `off` + `dryRun: true`。

**只出候选计划，不代领**。`enqueue: true` 才真正 spawn，且仅在 `mode ≠ off` 时生效。

### `task_next` / `task_claim`
`task_next` = 「我该干什么」（只读）。
`task_claim` = 领取（写租约，带 `fencing_token`）。准入四道闸门。

> 插件**不代领**。worker 必须自己 claim。

### `task_heartbeat`
续租。只认 `fencingToken` 能力凭证，**不绑身份**。续租失败 = 立刻停手。

> 建议 TTL ≥ 一轮工作的正常耗时。60 s 用于生产期，审计期由系统延到 600 s（见 [03](03-租约与防重放.md)）。

## 三、证据与治理

### `evidence_submit`
产物须**真实存在**；`acceptance` 机器判定；带来源分级（仅 `verified` 能支撑完成）；须可确定生产实例。

### `verify_done`
要求：证据 `verified` + **审计独立**（`producer ≠ auditor`，职务在白名单）+ 依赖全 done + 对应阶段闸门 passed。

**不要传 `auditor_instance`**——服务会用调用者自己的实例名。传了反而要做一致性校验。

### `pass_gate`
五段：`research` / `design` / `build` / `audit` / `deliver`。

> 顺序：**先 `pass_gate` 再 `verify_done`**，否则收到「阶段闸门未通过」。

### `decision_record`
L0–L2 决策。记「选了哪个选项、为什么」。

## 四、子 Agent 与团队板

### `agent_spawn`
三种组装策略（Team member / activation / provider）。Team 满**自动退回 activation**。

| 参数 | 说明 |
|---|---|
| `capability` | 能力包（不是职务枚举） |
| `task` | 初始任务文本 |
| `contextPack` | 上下文事实/指针（每行一条） |
| `agentPreset` | 显式指定预设；**默认继承父**（见 [06](06-容量与宿主依赖.md)） |
| `maxDepth` / `timeoutMs` | 递归深度 / 超时 |
| `enabled` | worker 契约是否启用 |

> Team 路径返回 `via: spawnTeammate` + `ownerCapable: true`；退回 activation 时 `ownerCapable: false`，**子实例不能当 TeamTask owner**。

### `agent_message` / `agent_reap`
投消息 / 回收空闲子 Agent（默认 dry-run，只释放/归档，**不硬删 journal**）。

### `team_status`
读团队板与派生子实例。**缺 caller 即拒**（`caller-required`）。

### `board_task_create` / `board_task_update`
团队板任务。**是投影，不是权威**——`update` 需 `expectedRevision`（CAS）。

## 五、记忆与工程

### `memory_load` / `memory_writeback`
`load`：按需读管理区的任务卡 / STATE / 报告，返回紧凑文本 + 引用（**不自动注入**）。
`writeback`：写回结论、证据指针、下一步；有任务卡时做 CAS。

### `project_init`
初始化工程区 + 管理区骨架。**默认 dry-run**，只 `git init`（不 commit）。

## 六、放活与限额的对照

| 现象 | 该调哪个 |
|---|---|
| 「同时做不了更多」 | `maxParallel` |
| 「派得太快」 | `dispatchRatePerSecond` |
| 「派出去了但没人领，越积越多」 | `maxQueuedTasks` |
| 「预算烧完就再也不派了」 | 加预算（**重试无用**，见 [02](02-派发与闸门.md)） |
| 「宿主说 active child limit」 | **调本插件任何参数都无效** → 看 `subagentMaxActive`（见 [06](06-容量与宿主依赖.md)） |
| 「某个协调域满员，别的域却在闲」 | 分区 `maxActive`（不是 `maxParallel`） |
