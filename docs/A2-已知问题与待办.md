# A2 · 已知问题与待办

> **附录编号**：`A1`/`A2` 不占正文 `01`–`14` 的递归序列——正文讲「怎么运作」，附录放「猜想」与「已知问题台账」。

> **这是问题台账，不是缺陷清单。** 只记「已经知道、但故意先不修」的东西。
>
> 收录标准：**能复查**（说得清现象和复现入口），**有明确的影响面**（会不会影响插件功能），**有修复的触发条件**（什么情况下必须动手）。说不清现象的进不来——含糊的抱怨没法验证，也没法验收。
>
> 不收：待实现的新能力（那是设计文档的事）、已修的问题（那是 commit 和报告的事）。

## K-01 · 面板侧的显示毛病

**已知**：用户反馈「插件面板侧有点毛病」，但未给出具体现象（哪一屏、什么情况下、期望与实际差在哪）。

**为什么不急着修**：
- 不影响插件功能——面板是**只读投影**，投影错了不会让图错、不会让验收错；
- 现象未具体化，动手修等于赌。**先等一次可复现的观察**，比猜着改更省事。

**它该被修的信号**（任一出现就升级）：
1. 显示的错误会让人**做出错误决策**（例如把"未运行"看成"正在运行"，从而误判能不能再派活）；
2. 面板读到的是**陈旧状态却没标陈旧**——这条最危险，因为它会伪装成事实；
3. 有人开始绕过面板直接查 journal「因为面板不可信」。

**下次复现时请记三件事**：哪一屏、当时的 `graph_status` 摘要、期望看到什么。

> 备注：面板侧车（`src/ui-server.ts`）读的是 `uiSnapshot`，与 `graph_status` 同源；若两者不一致，那本身就是一个明确的可查线索（说明投影层有分叉），比"面板有点毛病"更能定位。

## K-02 · 千级 Agent 的可视化不便

这条不是"某个控件坏了"，而是**当前面板的交互形态是按「几十个节点」设计的**，一千个节点时它会变成"能打开但没法看"。

**具体的机制瓶颈**（都在代码里，不是感觉）：

| 瓶颈 | 位置 | 千级时的表现 |
|---|---|---|
| 节点分页默认 50、上限 500 | `graph_status({limit, offset})` | 1000 节点要翻 20 页；没有"按 stage / 按状态 / 按分区"的聚合入口 |
| 在跑行只留最近 50 条 | `dispatchView().active.rows`，超出标 `truncated` | 想看"哪 300 个在跑"看不到，只看到尾部 50 条 |
| 闸门历史是环缓冲 | `gateHistory`（窗口内累计） | 只能回答"这段时间主要卡在哪"，不能回答"第 3 分钟那一波是谁挡的" |
| 邻域摘要按 `maxNeighbors` 截断 | `neighbor_digest` / `organization_review.next` | 千级时永远是"截断视图"，且 `caveatFlags` 会一直挂着 `truncated` |
| 工作区只读侧车 | `src/ui-server.ts`（`/l0-control/*`） | 没有游标/增量协议，面板要么全量要么没有 |

**为什么不急着做**：
- 插件本身的运行不依赖面板。真要看全局，`graph_export` 导出的投影 + journal 是权威且完整的；
- 千级协作任务**本身还没实跑过**（见 [06](06-容量与宿主依赖.md)：32 稳、54 就已经把宿主 inspector 打崩）。**先解决能不能跑到 256，再谈 256 好看不好看**——反过来做是给一个跑不起来的东西做仪表盘。

**如果要做，方向已经清楚**（记下来免得重复推演）：
1. **先聚合、后明细**：面板首屏只给 `counts by stage / status / capability / partition`，点进去才拉明细；一千个节点的高层状态用几百个字符就能说清。
2. **服务端游标而不是全量**：`active.rows` 之类改成 `(cursor, limit)` 增量协议，面板虚拟滚动；截断要给出"还有多少条"而不只是标 `truncated`。
3. **异常优先**：千级下默认只显示"有问题的"（阻塞、租约过期、卡在 submitted、证据 `unknown`），正常的折叠成计数——这和 [12 编排感知](12-agent节点编排感知.md) 里"正常的不占字符"是同一条原则。
4. **导出兜底**：面板永远提供"把当前视图导出成文件"，复杂分析走离线工具（`tools/analyze-session.mjs` 已有先例）。

**触发条件**（满足其一就必须做）：
- 真跑到 200+ 并发，且有人需要**同时**看这些节点的状态；
- 出现"因为看不全而漏掉一个卡住的节点"这类事故；
- 上游 inspector 崩溃修好、并发爬过 128（那时面板会成为下一个瓶颈）。
