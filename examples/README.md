# examples

两目录协议（**工程区 / 管理区**）的最小样本。看过这些就知道这套东西在文件系统上到底长什么样。

## 两个样本

### `project/` + `project-管理区/` —— 标准两目录配对

```
project/                工程区：代码与产物（这里是示例，实际就是你的项目）
project-管理区/         管理区：状态卡 / 设计 / 任务 / 报告，独立 git 仓库
  INDEX.md                入口索引
  STATE.md                状态卡（当前进展、最近几轮、下一步）
  designs/BOOTSTRAP.md    设计文档
  tasks/BOOTSTRAP.md      任务卡
```

**为什么要两个目录**：状态、设计、任务、报告和代码的**生命周期不同**。代码要评审、要回滚；状态卡每轮都变。混在一个仓库里，要么状态变更污染代码历史，要么代码评审被状态噪音淹没。

### `smoke-demo/` —— 管理区嵌在项目内

```
smoke-demo/
  管理区/{INDEX,STATE,designs,tasks}
```

适合小项目：不想多一个仓库时，把管理区当子目录。代价是两边历史绑在一起。

## 这些示例里**没有**什么

- **没有 `.l0-control/`**：那是插件运行时状态（journal、锁），由插件在你自己的机器上生成，不该随示例分发
- **没有 `.git/`**：示例不是独立仓库，避免嵌套 git
- **没有真实凭据/令牌**

## 怎么用

1. 复制一个样本到你的工作位置（或直接在你现有项目旁建一个 `-管理区` 目录）
2. 用 `project_init` 生成骨架，或按样本手写 `INDEX.md` / `STATE.md`
3. 在 DSH 里启用协作后，插件的状态落在 `.l0-control/`（**自动生成，别提交**）
4. 管理区建议单独 `git init`，并把 `*.log`、运行时状态写进它的 `.gitignore`

## 一个容易踩的坑

`STATE.md` 这类状态卡会越长越长。建议给它定一个硬上限（本仓库的管理区用的是 15000 字符），超了就压缩——**状态卡是给人快速接手用的，不是历史归档**；历史留在 `reports/` 里。
